## Context

Поточний стан (див. `proposal.md` — Why):

- Blade-шаблони підключають статичні файли з `public/assets/css`: `app.css` (455 рядків, шапка/футер/бургер) та `index.css` (894) у `layouts/app`, а сторінкові `pages/{about,blog,contact,extra,full-menu,menu}.css` і `auth/login.css` — через `@yield('link.css')`. Усього ≈3000 рядків, 9 файлів, 13+44+17+11+11+16+17+14 пікселових `font-size`.
- Кожен сторінковий файл заново оголошує `:root` (кольори/шрифти/transition) та власні `.d-flex`, `.max-text`, `.section-fashion`, `.fashion-container`; `extra.css` дублює блок блогу з `index.css`.
- У `layouts/app` шляхи ресурсів відносні (`../assets/css/index.css`, `../../../assets/js/...`): працює лише на глибині одного сегмента, на `/foodzero/menu/full` — 404.
- Блоки шапки, футера, форми, слайдера — у `partials/` і `index.blade.php`; JS — два невеликі файли без перевірок на наявність елементів.
- Збірки фронтенду немає: у `workspace-84` Node 16, `package.json` розрахований на Vite 6/Tailwind 4 (Node 18+), але Blade `@vite` не використовує (див. CLAUDE.md). Хостовий Node — 20.12.
- Тести ходять у dev-БД `zero`; у ній зараз немає ні постів, ні страв — тому blog/full-menu порожні, а посилання `post/1`, `post/2` на головній дають 404.

Аудит виконано через headless Chrome (puppeteer-core): знімки 375/768/1024/1440, помилки консолі, 404, горизонтальний скрол, розміри всіх `<img>`.

## Goals / Non-Goals

**Goals:**
- SCSS як єдине джерело стилів, закомічений скомпільований CSS на тих самих URL — Blade мінімально змінюється.
- Один шар токенів і міксинів; прибрати дублі та невалідний CSS.
- Усунути дефекти адаптиву/розмітки/контенту/адмін-лейаута з специфікацій.
- Регресії на десктопі 1440 перевіряються знімками до/після.

**Non-Goals:**
- Перехід на Vite/Tailwind-збірку для Blade, мінімізація/версіонування асетів, CSS-in-JS.
- Редизайн: палітра, шрифти (Rufina/Lato/Inter) і композиція секцій лишаються.
- Зміни `public/admin/dist/**`, `public/admin/plugins/**`, стилів AdminLTE; міграція адмінки на SCSS.
- Нова функціональність (бронювання, пошук, підписка на розсилку), зміни API/БД/маршрутів.
- Заміна слайдера на бібліотеку (лише захист від помилок і доступність).

## Decisions

**1. Компіляція: `sass` (Dart Sass) як devDependency, запуск на хості (Node 20) з комітом результату.**
Скрипти `scss:build` = `sass --no-source-map --style=expanded resources/scss:public/assets/css`, `scss:watch` додає `--watch`. Скомпільований CSS комітимо — Laradock не потребує Node.
*Альтернативи:* (а) Vite + `laravel-vite-plugin` — потребує Node 18+ у контейнері й переписування `@vite` у Blade, виходить за межі; (б) `laravel-mix` — застарілий; (в) `node:20` Docker-контейнер — запасний варіант, якщо на хості Node зміниться (команда описується в README). Mixed-мова `package.json` (`"type": "module"`) не заважає CLI `sass`.

**2. Структура `resources/scss/` (Sass-модулі, `@use`, без `@import`).**
```
resources/scss/
  abstracts/ _tokens.scss _breakpoints.scss _mixins.scss _functions.scss
  base/      _reset.scss _typography.scss _utilities.scss
  components/ _header.scss _burger.scss _footer.scss _buttons.scss _blog-card.scss _slider.scss _reservation-form.scss _banner.scss
  pages/     _home.scss _menu.scss _full-menu.scss _blog.scss _about.scss _contact.scss _post.scss
  app.scss  index.scss  pages/*.scss  auth/login.scss   // тонкі входи
```
Вхідні файли відповідають наявним URL, тож `@yield('link.css')` і `layouts/app` не змінюють контракт. Дедуплікація: `extra.css` розкладається по `components/_blog-card.scss`/сторінкових файлах. *Альтернатива:* один монолітний `main.css` — гірше для кешу сторінкових стилів і потребує змін у шаблонах.

**3. Токени — CSS custom properties, згенеровані з Sass-мапи; брейкпоінти й шкала — Sass-змінні.**
Палітра/шрифти/transition лишаються `--color-*`, `--font-*`, `--transition-all` (існуючі імена зберігаємо для зворотної сумісності й інлайнових стилів у Blade), але виводяться з `_tokens.scss` рівно в `app.css`. Брейкпоінти: `sm 500` → `$bp-sm: 576px`, `md 768px`, `lg 1024px`, `xl 1280px`, використання через `@include respond-down(md)`. Старі 500/700/950/1000/1150 мапляться на найближчий новий; проміжні ширини 820 і 1100 перевіряються вручну. Типографічні розміри — `clamp()` через міксин `fluid-type()` для найбільших заголовків (85/75/55 px), інакше фіксовані значення з шкали.
*Альтернатива:* лише Sass-змінні без custom properties — не дає перевизначення в інлайні й не відповідає наявним `var(--…)` у шаблонах.

**4. Парність, а не редизайн: знімки до/після як приймальний тест.**
Скрипти аудиту (puppeteer-core, лежать поза репозиторієм у scratchpad) переносяться в `tools/visual-audit/` (devDependency лише там, не в `package.json` додатку) і зберігають базові знімки 1440 перед міграцією. Порівняння — піксельний diff з допуском; навмисні відмінності (виправлення адаптиву) перелічені в завданнях.

**5. Виправлення ресурсів: `asset()` у `layouts/app` та `auth/login`.**
`<link href="{{ asset('assets/css/index.css') }}">`, аналогічно для JS і favicon; `lang="{{ str_replace('_','-', app()->getLocale()) }}"` та `@yield('meta.description')` із значенням за замовчуванням. Контентна мова сайту — англійська, тож `lang="en"` фіксується в конфігу, а не береться з локалі додатку (`APP_LOCALE`, яка може бути `uk`).

**6. JS: охоронні перевірки та доступність без нових бібліотек.**
`index-slider.js` — ранній вихід, коли `.mySlides` немає; змінні з `var` → `const/let`, інлайнові `onclick` (якщо є) → слухачі. `adaptive-menu.js` — перемикач стає `<button class="adaptive-icon" aria-label aria-expanded aria-controls>`; Escape, повернення фокуса, `inert`/`hidden` для закритого меню (щоб приховані пункти не ловили Tab). Для меню додаємо `overflow-y: auto` і `100dvh`.

**7. Декор без накладань: у потоці або з `pointer-events: none` та резервом місця.**
Декоративні `leaf`/`blueberry`/томат у `menu-content`, `about` тощо переходять з абсолютного позиціонування на `grid`-область або `position:absolute` усередині блоку з достатнім `padding`/`min-height`, а на `< md` ховаються (`display:none`) або зменшуються до кута секції. Критерій — відсутність перетину bounding box із заголовком (перевіряється в audit-скрипті).

**8. Одиничний `h1`: зміна тегів, не стилів.**
Секційні `h1` → `h2` із збереженням класів (`.section-cook-title`, `.fashion-title`, `.menu-title` тощо) і `font-size`/`margin` на самому класі, а скид UA-стилів `h1/h2` у `_reset.scss` гарантує візуальну тотожність.

**9. Дані та empty state: посилання формуються з БД.**
`HomeController@index` передає найновіші `Post::latest()->take(2)`; шаблон показує секцію лише при наявності постів. `blog` і `full-menu` отримують `@forelse`/`@empty` з компонентом `partials/empty-state`. Статичний «Julie Christie / October 17,2025» у головній береться з даних поста (автор — `clients`, дата — `created_at`), а де такого поля немає — прибирається.

**10. Адмін-лейаут — точкові виправлення, vendor не чіпаємо.**
Видалити CDN Bootstrap 5 із зламаним URL (AdminLTE 3 несе власний Bootstrap 4 через `adminlte.min.css` і `bootstrap.bundle.min.js` — змішування BS5+BS4 прибирається); дублі `admin.js`/`colorbox` видаляються, шлях до `admin.js` — `/admin/js/admin.js`; закрити `</ul>`; ключ TinyMCE → `config('services.tinymce.key')` з `TINYMCE_API_KEY` у `.env`/`.env.example` (порожній у прикладі). Старий ключ у git-історії вважається скомпрометованим — рекомендація ротації зазначена в завданнях. Login: прибрати `family=Arial` з `auth/login.css` (`@import`) і використати системний стек.

## Risks / Trade-offs

- [Візуальна регресія при злитті токенів/брейкпоінтів] → базові знімки 375/768/1024/1440 до міграції, diff після кожного SCSS-кроку, міграція по одному файлу за раз.
- [Скомпільований CSS у git шумить у diff і може розійтися з SCSS] → збірка детермінована; перевірка в завданнях: «збірка → `git diff` порожній»; у README — правило «CSS не правимо вручну», у шапці файлу коментар `generated`.
- [Хостовий Node не збігається в команди] → команда в README + запасний `docker run node:20`; результат у git, тож Laradock не залежить від збірки.
- [Зміна `h1` → `h2` ламає SEO/якорі] → класи збережено, якорі `#category-N` на `id`, не на теги; перевірка в audit-скрипті.
- [Видалення BS5 CDN із адмінки ламає сторінки, що спиралися на нього] → пройти кожну адмін-сторінку (`dashboard`, `post`, `category`, `menu`, `members`, `reservation`) до і після; якщо клас доступний лише в BS5, замінити на BS4-еквівалент.
- [Тести працюють на dev-БД] → не додаємо `RefreshDatabase`; перевірки порожнього стану — через окремі Blade-рендери з підставленими колекціями (feature-тест із `View::share`/`Pest`-стилем без запису в БД) або ручним сценарієм у завданнях.
- [Ключ TinyMCE уже у git-історії] → лише рекомендація ротації; переписування історії поза межами зміни.

## Migration Plan

1. Зафіксувати базові знімки й звіт аудиту (до змін).
2. Виправити підключення ресурсів і JS-помилки (швидкий виграш, без SCSS) — окремий коміт.
3. Додати `sass`, скрипти, скелет `resources/scss/` і перекомпілювати наявні CSS 1:1 (копіюванням у SCSS без рефакторингу) — діф знімків має бути нульовим.
4. Винести токени, міксини, утиліти; видалити дублі; нормалізувати брейкпоінти й шкалу розмірів — діф лише у допустимих місцях.
5. Виправити адаптив (декор, банери, бургер, заголовки), розмітку (h1, `<a>`, `<span>`), контент, empty state.
6. Адмін-лейаут і логін.
7. Фінальна верифікація: аудит-скрипт 4 ширини × 7 сторінок = 0 помилок консолі/404/скролу, `php artisan test`, `vendor/bin/pint` лише по змінених PHP-файлах.

Відкат: кожен крок — окремий коміт у гілці `feature/design-audit-scss`; повернення — `git revert` коміту. Скомпільований CSS в git дозволяє відкотити стилі, не маючи Node.

## Open Questions

- Чи лишається мова інтерфейсу сайту англійською (поточний контент) — тоді `lang="en"` фіксований; формулювання empty state узгодити українською чи англійською з власником продукту.
- Яке значення телефону канонічне (`+86 852 346 000` у шапці проти `+1+86 852 346 000` у футері/меню) — у завданнях використаємо `+86 852 346 000` як у шапці, якщо власник не скаже інакше.
