## Purpose

Визначає, як стилі публічного сайту Food Zero пишуться на SCSS, збираються у статичний CSS і діляться єдиними дизайн-токенами, щоб вигляд сайту не розходився між сторінками.

## ADDED Requirements

### Requirement: Стилі сайту мають SCSS-джерела
Система SHALL зберігати вихідні стилі публічного сайту та сторінки логіну у файлах SCSS в `resources/scss/`, а в `public/assets/css/` віддавати скомпільований CSS з тими самими шляхами, які вже підключають Blade-шаблони.

#### Scenario: Кожен підключений CSS має SCSS-джерело
- **WHEN** перевіряється будь-який файл у `public/assets/css/` (`app.css`, `index.css`, `pages/*.css`, `auth/login.css`)
- **THEN** для нього існує відповідний SCSS-вхід у `resources/scss/`, а сам CSS позначений як згенерований

#### Scenario: Сайт працює без збірки на сервері
- **WHEN** проєкт розгортається в Laradock без Node 18+
- **THEN** сторінки відображаються зі скомпільованих файлів `public/assets/css/`, закомічених у репозиторій

### Requirement: Збірка відтворювана однією командою
Система SHALL надавати одну документовану команду, яка компілює всі SCSS-входи в CSS, та команду спостереження за змінами; повторний запуск без змін у джерелах SHALL давати ідентичний результат.

#### Scenario: Повна збірка
- **WHEN** розробник запускає команду збірки
- **THEN** усі CSS-файли в `public/assets/css/` перегенеровано без помилок і без попереджень про застарілий синтаксис

#### Scenario: Збірка детермінована
- **WHEN** команду збірки запущено двічі поспіль без змін у джерелах
- **THEN** `git diff` після другого запуску порожній

### Requirement: Єдиний шар дизайн-токенів
Система SHALL визначати кольори, шрифтові сімейства, типографічну шкалу, відступи, часи переходів і брейкпоінти в одному місці, а сторінкові стилі SHALL посилатися на ці токени й не повторювати `:root` та шістнадцяткові кольори палітри.

#### Scenario: Токени не дублюються
- **WHEN** скомпільовані CSS-файли сторінок перевіряються на оголошення `:root`
- **THEN** змінні палітри та шрифтів оголошені рівно в одному спільному файлі

#### Scenario: Зміна кольору палітри
- **WHEN** змінюється значення основного кольору в токенах і виконується збірка
- **THEN** новий колір застосовується на всіх сторінках без правок у сторінкових файлах

#### Scenario: Єдиний набір брейкпоінтів
- **WHEN** перевіряються `@media`-запити у скомпільованому CSS
- **THEN** вони використовують лише визначений набір брейкпоінтів, а не довільні значення (500/700/950/1000/1150)

### Requirement: Спільні утиліти й компоненти визначені один раз
Система SHALL визначати спільні класи (`.d-flex`, `.d-grid`, `.container`, `.max-text`, `.text-right`) і повторювані компоненти (картка блогу `.section-fashion`/`.fashion-container`) в одному місці та підключати їх на всіх сторінках, де вони потрібні.

#### Scenario: Немає повторних оголошень
- **WHEN** скомпільований CSS усіх сторінок аналізується на однакові селектори з однаковими деклараціями
- **THEN** жоден із перелічених селекторів не визначений у більше ніж одному вхідному файлі, окрім навмисних перевизначень для іншого брейкпоінта

#### Scenario: Візуальна парність на десктопі
- **WHEN** порівнюються знімки сторінок до та після міграції на ширині 1440 px
- **THEN** відмінностей, не передбачених іншими вимогами цієї зміни, немає

### Requirement: Скомпільований CSS не містить невалідних декларацій
Система SHALL не містити в CSS декларацій, які браузер відкидає: значень без одиниць виміру для тривалості, нестандартизованих вендорних значень та експериментальних значень без запасного варіанта.

#### Scenario: Тривалість анімації має одиницю
- **WHEN** перевіряється анімація появи слайдів
- **THEN** `animation-duration` задано з одиницею (`1.5s`), і анімація справді триває 1.5 секунди

#### Scenario: Вирівнювання без експериментальних значень
- **WHEN** перевіряються декларації `text-align` та `align-items`
- **THEN** значення `-webkit-center` і `anchor-center` відсутні, а вирівнювання досягається стандартними засобами
